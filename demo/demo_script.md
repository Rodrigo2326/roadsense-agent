# Demo script — target 2:40–2:55

The judging criterion is whether a real Decider decision is visible and whether it
changes what happens next. So the terminal is the demo: the trace is the product.

Run everything on the EC2 box so the model is already warm — the 39.8 s load must not
happen on camera. Start each command in a shell that has already run one throwaway
query, so the weights are resident.

---

## 0:00–0:20 — The claim

> "This is RoadSense. Ask it about a road scene and it does not guess from one look.
> It decides what evidence it needs, goes and gets it, and decides again once it sees
> what came back. A 2-billion-parameter Strands Decider model makes those choices;
> Amazon Bedrock only writes up what was actually found."

On screen: `docs/decision-pattern.md`, the four-box diagram.

## 0:20–1:10 — The sequential decision

```bash
python -m roadsense.cli \
  -q "What vehicles appear and what text can be read on the sign?" \
  -i demo/images/synthetic_sign_clear.jpg
```

Let the trace print. Point at three things, in this order:

1. **Step 1 picks `detect_objects` at 0.776** — and read the distribution aloud:
   `detect_objects=0.832, read_sign_text=0.158`. "It is not certain, and it should not
   be. Both are reasonable openings."
2. **Step 2 picks `read_sign_text` at 0.952.** "That jump is the point. The state it
   read this time contains what the detector found. The decision changed because the
   evidence changed."
3. **`P(evidence sufficient)` climbing 0.196 → 0.273 → 0.572.** "A second question,
   answered in the same call, for free."

## 1:10–1:50 — Knowing when to stop

```bash
python -m roadsense.cli -q "What text can be read on the sign?" \
  -i demo/images/synthetic_sign_illegible.jpg
```

> "Same sign, degraded until OCR returns nothing. It does not invent the word. It
> says no readable text could be extracted, and it says what the detector *did*
> confirm."

Then, immediately, with no image at all:

```bash
python -m roadsense.cli -q "What vehicles appear in this photo?"
```

> "No image. The menu it is offered contains only two options, because the two vision
> tools are illegal here — and it asks for better evidence at 0.962 confidence. The
> guardrail is in code; the model never had to be trusted to respect it."

## 1:50–2:20 — The pattern, with no image in it

## 2:20–2:50 — The measurements, including the losses

On screen: `eval/results/report_full.md`.

> "37 cases, four selectors through the same loop. Decider is not the winner on every
> row, and the report says so. A keyword rule gets the tool set exactly right more
> often than Decider does — partly because the ground truth is derived from the
> question wording, which is exactly what a keyword rule reads.
>
> What the keyword rule cannot do is notice that the file is missing. On the
> invalid-input cases it answers anyway, 2 out of 5. Decider gets 5 out of 5.
>
> And here is the one it got wrong: a sign degraded until OCR reads a single letter
> at 0.85 confidence. Confidently wrong input, confidently wrong output. We report it
> rather than tuning the threshold until it disappears."

## Recording notes

- Terminal at ~110 columns; the trace lines wrap badly below 100.
- Decider decisions take ~3 s each. Do not cut them — the pause *is* the work. Cut
  the 40 s model load instead, by pre-warming.
- Have `eval/results/report_full.md` open in a second pane rather than scrolling to
  it live.
- Say "Strands Decider 2B" at least twice; the submission is indexed on it.
- Do not say "safe", "safety", "warn the driver" or "detects hazards" at any point.
